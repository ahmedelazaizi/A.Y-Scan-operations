# PRD — نظام إدارة مركز التحاليل والأشعة

## 1. الملخص
نظام عربي RTL ثنائي اللغة لإدارة دورة المريض من التسجيل إلى الطلب والفاتورة وسحب العينة وإدخال النتائج ومراجعتها وتسليمها، مع دعم خدمات الأشعة، المخزون، التأمين، الأطباء، الزيارات المنزلية، التقارير والتكامل مع أجهزة المختبر. الصور في `photos/` مرجع UX لنظام قائم؛ ليست مواصفة تنفيذية ولا مصدرًا لبيانات حقيقية.

## 2. المشكلة والأهداف
- تقليل الإدخال المكرر وأخطاء مطابقة العينة بالمريض.
- جعل حالة الطلب والعينة والنتيجة والدفع مرئية لكل دور.
- تسريع إصدار تقارير موثوقة قابلة للطباعة والمشاركة الآمنة.
- توحيد التسعير والباقات والتأمين والعمولات والمخزون.

**Non-goals في MVP:** PACS كامل، تشخيص آلي، تطبيق مريض أصلي، محاسبة عامة كاملة، وامتثال قانوني تلقائي.

## 3. المستخدمون والصلاحيات
- موظف الاستقبال: المرضى، الطلبات، الفواتير، المدفوعات وفق حدود.
- فني السحب: قائمة العينات، barcode، حالات السحب والرفض.
- فني المختبر: التشغيل وإدخال النتائج.
- مراجع/استشاري: اعتماد النتائج وإعادة الفتح المعلّلة.
- فني الأشعة/طبيب الأشعة: جدولة الفحص، التقرير، المرفقات والاعتماد.
- مدير الفرع: التشغيل والتقارير والمخزون.
- محاسب: الإيرادات والمصروفات والتسويات.
- مسؤول النظام: المستخدمون، RBAC، الإعدادات، السجل التدقيقي.
- طبيب محوِّل وشركة تأمين: قنوات وصول محدودة حسب الصلاحية.

## 4. نطاق MVP
1. Patient Registry مع رقم ملف فريد، بحث وتعارضات الهوية.
2. Catalog للتحليلات وفحوص الأشعة والباقات، عربي/إنجليزي، units وreference ranges حسب الجنس/العمر/السياق.
3. Orders: إنشاء الطلب، priority، fasting، الطبيب، التأمين، الملاحظات، الأسعار والخصم.
4. Specimens: barcode، نوع الأنبوب، collection، rejection reason، chain of custody.
5. Results: إدخال رقمي/نوعي، flags، comments، مراجعة واعتماد وإصدار PDF.
6. Billing: invoice، partial payment، refund/void بصلاحية، receipt.
7. Dashboard تشغيلي مع بحث وفلاتر وحالات واضحة.
8. RBAC، audit log، backup، notifications داخلية.

## 5. Phase 2
LIS عبر HL7/ASTM بعد إثبات نموذج البيانات، بوابة طبيب/مريض، إشعارات WhatsApp/SMS عبر مزود معتمد، home visits، insurance claims، مخزون متقدم، تقارير أشعة structured، تكامل DICOM/PACS، multi-branch وoffline queue.

## 6. المتطلبات الوظيفية
- **FR-01:** يمنع النظام إنشاء مريض مكررًا دون تحذير ومراجعة.
- **FR-02:** لا يتحول الطلب إلى Collected دون تسجيل جامع ووقت وعينة/barcode.
- **FR-03:** كل نتيجة تحمل value/unit/reference range/flag ومصدر الإدخال.
- **FR-04:** لا تصدر النتيجة قبل صلاحية المراجع؛ إعادة الفتح تنشئ سببًا وسجلًا.
- **FR-05:** الفاتورة تحسب الإجمالي والخصم والتأمين والمدفوع والمتبقي وتحتفظ بتاريخ التعديلات.
- **FR-06:** صلاحية الخصم والإلغاء والاسترداد قابلة للضبط حسب الدور والحد.
- **FR-07:** التقرير يعرض هوية المركز، المريض، الطلب، النتائج، الاعتماد، version وQR للتحقق.
- **FR-08:** المخزون ينبه عند حد الأمان وقرب الانتهاء، ولا يسمح بصرف كمية سالبة.
- **FR-09:** تكامل الجهاز يعزل raw message عن parsed result ويعرض فشل المطابقة للمراجعة.
- **FR-10:** كل API محمي بمصادقة وتفويض وتسجيل audit للأحداث الحساسة.

## 7. سير الحالات
Order: Draft → Confirmed → In Progress → Completed/Cancelled.
Specimen: Pending → Collected → Received → Processing → Rejected/Completed.
Result: Draft → Entered → In Review → Approved → Released → Amended.
Invoice: Open → Partially Paid/Paid → Refunded/Void.
الحالات قابلة للضبط لكن انتقالاتها audited ولا تُحذف تاريخيًا.

## 8. الأشعة
MVP يسجل modality، body part، protocol، appointment، findings/impression، الطبيب المعتمد ومرفقات التقرير. صور DICOM/PACS والتوزيع الخارجي Phase 2. لا يقدم النظام تشخيصًا طبيًا آليًا.

## 9. غير الوظيفي والخصوصية
- توافر مستهدف 99.5% شهريًا بعد pilot، وRPO/RTO يحددهما التشغيل.
- p95 للقراءات الشائعة أقل من 500ms في الحجم المستهدف.
- RTL وArabic/English، keyboard/accessibility، responsive.
- تشفير أثناء النقل والتخزين، secrets خارج المستودع، least privilege، MFA للأدوار الحساسة.
- retention، consent، export/delete وفق القانون المحلي؛ مراجعة قانونية إلزامية قبل التشغيل.
- لا تُستخدم صور العينة كبيانات إنتاج ولا تُنسخ أسماء/هواتف حقيقية.

## 10. مؤشرات النجاح والقبول
زمن تسجيل الطلب، زمن تسليم النتيجة، نسبة العينات غير المطابقة، نسبة إعادة إدخال النتائج، دقة التسوية اليومية، adoption لكل دور، وعدد حوادث الخصوصية. قبول MVP يتطلب E2E ناجحة للتسجيل→طلب→عينة→نتيجة→اعتماد→فاتورة، صلاحيات سلبية، استعادة backup، وتوقيع UAT من التشغيل والمختبر والمحاسبة.

## 11. الافتراضات والأسئلة المفتوحة
نفترض فرعًا أوليًا وعملة محلية واتصالًا دائمًا. نحتاج قرارًا حول الدولة واللوائح، حجم العينات، أجهزة/بروتوكولات فعلية، سياسة retention، مزود الرسائل، PACS، قواعد reference ranges، وسير اعتماد النتائج. راجع [TRACEABILITY](TRACEABILITY.md) و[REVIEW_CHECKLIST](REVIEW_CHECKLIST.md).
